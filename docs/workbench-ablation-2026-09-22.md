# Smoji 工作台消融实验（2026-09-22）

基线源码：`e10929d8a9bdf0a8e1b7ac87b5a33bc58cf6653b`。本次只增加实验脚本和报告，不将任何消融配置应用到产品。

## 阅读范围与实验问题

项目有两条独立路径：`packages/smoji` 是原生 TypeScript 选择器 SDK；`apps/workbench/index.html → src/main.tsx → WorkbenchProvider → App` 是实际 React 工作台。旧 `main.ts` 及其样式、静态 HTML 仍留在仓库，不能把 SDK 的体积预算当作整个工作台的体积。

工作台启动时并行读取同版本清单和历史资源别名，二者完成后才挂载并迁移本地存储。图库先挂载 72 项，再由 IntersectionObserver 逐批扩展；已有 DOM 不会回收。卡片使用 React.memo、CSS content-visibility 和解码后显现动画，卡片快捷操作使用 Radix Tooltip。导出和帮助弹窗按需加载。

实验分别回答：上述机制实际节省多少；哪些只是视觉选择；哪些虽有成本却承担数据兼容性契约，不能直接删除。

## 方法与复现

在 Windows 修改实验脚本；生产构建和 Chromium 在 Debian WSL2 ext4 镜像内运行。每组采用同一份真实清单：35 个分类、5,830 张表情，入口 bilibili 284 张，最大分类 xiaohuangji 482 张。

```powershell
linux-task.ps1 -Mode build -Project 'D:/Forgejo/Smoji' -Command 'pnpm install --frozen-lockfile && pnpm exec playwright install chromium && pnpm generate:packs && node scripts/ablate-workbench.mjs'
```

脚本：[`scripts/ablate-workbench.mjs`](../scripts/ablate-workbench.mjs)。通过 Vite 插件构建独立变体，不修改产品源码，也不新增依赖或运行时实验开关。每个替换点都有断言，源码漂移导致替换失效时明确失败。

- 桌面 1440×900、触屏手机模拟 390×844；Chromium、4 倍 CPU 降速、40 ms 网络延迟、1.25 MB/s 下载速率。
- 每个变体、每个视口先预热一次，随后测量五次。轮转执行顺序，使用新浏览器上下文、禁用缓存、中位数汇总。
- 性能轮次的图片统一替换为同一 SVG，以隔离远端 CDN、文件大小和动画内容；HTML、JS、CSS、字体和清单仍实际请求，文本资源通过 gzip 提供。图片 route.fulfill 不作为受控带宽测量。
- “图库就绪”指第一张可操作卡片挂载后再经过两次 requestAnimationFrame，不等于全部图片就绪，也不是线上 LCP。
- “启动阻塞”是就绪后固定观察窗口内 `sum(max(longTask.duration - 50, 0))`，不是 Lighthouse TBT 或真实 INP。
- “打开详情”记录程序化 click 至两次 requestAnimationFrame，并断言弹窗实际出现；它是实验交互延迟，不是用户输入的 INP。所有构建统一插入卡片渲染计数。
- 滚动前加载完整的 482 项，返回顶部；以相同的 40 帧往返滚动路径比较主线程时间和帧间隔，避免不同加载量造成虚假收益。
- 视觉对照使用入口分类真实 CDN 图片，分别比较系统字体、取消图片显现动画、移除卡片装饰、常显快捷操作、舒适密度，另留深色基线。视觉截图使用正常 CPU；没有做真人任务成功率或偏好调查。

实验产物位于构建镜像 `.tmp/ablation/`。应通过 `linux-task.ps1 -Mode path` 查询镜像，仅复制 `results.json`、截图等指定产物到 Windows，不能反向同步源代码。

## 实验变体

| 变体 | 唯一移除项 | 保留的契约 / 限制 |
|---|---|---|
| baseline | 无 | 当前产品基线 |
| no-progressive | 72 项分批挂载限制 | 仍有 content-visibility、memo |
| no-memo | EmojiCard 的 React.memo | 事件与数据流不变 |
| no-containment | content-visibility: auto | 仍分批挂载；保留几何约束 |
| no-fonts | IBM Plex Web 字体导入 | 继续使用现有系统字体回退链 |
| no-reveal | 图片解码后的 350 ms 模糊显现动画 | 保留解码、错误状态、重试与防旧请求覆盖 |
| no-legacy | 启动后会删除的隐藏旧 HTML | 保留 React 挂载根和主题初始化 |
| no-tooltips | 卡片级 Radix Tooltip 实例 | 保留 aria-label，用原生 title 携带相同文案；其他位置 Tooltip 不变 |
| eager-dialogs | 帮助、数据预览的按需代码加载 | 两个弹窗改为静态导入 |
| no-aliases | 历史地址别名表内容 | **仅空本地存储场景的成本测量；删除会破坏旧数据迁移，不可直接采用** |

## 证据边界

当前干净检出生成的 `data/previews.json` 为空。部署 CI 另生成缩略图，所以本轮不能量化线上原图/缩略图的流量、动图解码、内存或电量收益。SDK 只验证构建、功能测试和现有体积门禁，本次浏览器消融聚焦工作台。

五次测量用于发现明显方向，不能替代统计显著性检验；小幅计时差异应结合取值范围、两个视口和确定性指标判断。无真人实验，不能从截图推导转化率、操作成功率或普遍审美偏好。

运行在桌面五轮、手机前三轮及第四轮三项完成后被会话中断。保留 83 条已完成记录，重新构建相同变体并对手机各组重新预热，再完成剩余 17 条；没有把失败或预热轮次混入结果。续跑可能带来跨批次环境差异，因此本报告不把几个百分点的差异宣称为确定收益。

## 已发现的验证问题

额外浏览器回归：`pnpm exec playwright test e2e/responsive-viewports.spec.ts e2e/keyboard-workflow.spec.ts --project=chromium` **35 项通过、1 项按原测试条件跳过**。该 Chromium 项目无触屏，跳过触屏专属用例；本次消融的手机上下文另设 `hasTouch: true`，但不替代完整真实手机/Safari 验证。

`pnpm typecheck`、`pnpm build`、`pnpm check:size` 已通过。`pnpm test` 共 135 项，134 项通过、1 项失败；所以整体 `pnpm check` **未通过**。

失败项是 `packages/smoji/test/previews.test.ts`。最初 Debian 缺少 `magick`，补装 Debian ImageMagick 7.1.1-43 后，失败变为 `scripts/generate-previews.mjs` 对动画帧执行 `-coalesce -clone 1 -delete 0--2` 时的 `UnableToCloneImage`。这在未修改产品代码的基线上复现；本轮没有绕过断言或把环境安装当作修复。正式优化/发布前应单独修复并重跑该测试。

生产隐藏 HTML 还被 `boot-failure.test.ts`、`audit-regression.test.ts`、`copy-format.test.ts`、`responsive-ui.test.ts`、`ux-regression.test.ts` 五个旧工作台测试文件作为输入。清理生产静态壳时应迁移测试夹具或淘汰已被 React 契约覆盖的旧测试，不能只删 HTML 后宣布全部门禁通过。

## 性能结果

完整 100 次正式记录、环境、体积与截图几何数据：[`workbench-ablation-2026-09-22.results.json`](workbench-ablation-2026-09-22.results.json)。环境为 Intel Core Ultra 7 255H、Node 24.19.0、Chromium 153.0.8010.12、WSL2 Linux 6.18.33.2。所有正式记录均无 `pageerror`，滚动结束卡片数均为 482。

下表单位均为 **ms**，各项为五次中位数。“滚动主线程”是整个固定滚动过程的累计时间，包括进入视口导致的首次布局、图片显现等工作，不是每帧耗时，也不是已稳定页面的纯滚动微基准。

| 变体 | 桌面图库就绪 | 手机图库就绪 | 桌面滚动主线程 | 手机滚动主线程 |
|---|---:|---:|---:|---:|
| 基线 | 1,375 | 1,254 | 2,323 | 1,840 |
| 去掉分批渲染 | 2,291 | 2,133 | 2,499 | 2,345 |
| 去掉卡片 memo | 1,335 | 1,283 | 2,327 | 1,852 |
| 去掉 content-visibility | 1,379 | 1,297 | 1,769 | 1,054 |
| 去掉 Web 字体 | 1,350 | 1,254 | 2,274 | 1,875 |
| 去掉图片模糊显现 | 1,336 | 1,272 | 1,146 | 1,299 |
| 去掉隐藏旧 HTML | 1,324 | 1,282 | 2,314 | 1,897 |
| 卡片 Tooltip 改 title | 1,301 | 1,240 | 2,443 | 1,792 |
| 弹窗改立即加载 | 1,353 | 1,279 | 2,326 | 1,810 |
| 清空别名表（仅诊断） | 1,228 | 1,134 | 2,268 | 1,883 |

**优先候选：去掉 350 ms 的模糊显现动画，保留解码和错误状态。** 桌面滚动累计主线程减少约 50.7%，手机减少约 29.4%；帧间隔 P95 分别由 101.2 → 62.0 ms、81.6 → 59.9 ms。手机首屏就绪没有改善，收益应描述为滚动/渲染成本降低，不能宣称全面提速。静态截图只能确认结束态不变，不能证明用户感知完全相同。

**保留分批渲染与 memo。** 去掉分批渲染使就绪时间在桌面/手机分别增加约 66.6% / 70.1%。基线桌面因哨兵自动触发，观察点已有 144 张，手机为 72 张；全量方案均为 284 张。去掉 memo 不一定拖慢启动，但打开详情额外渲染 144 / 72 张卡片，基线均为 0；桌面详情实验延迟从 151 → 184 ms，手机从 113 → 128 ms。只比较首屏会漏掉 memo 的实际作用。

**content-visibility 在这条滚动路径上没有获益。** 去掉它后主线程减少约 23.8% / 42.7%，帧间隔 P95 降至 54.0 / 56.7 ms。它仍可能有其他离屏绘制收益，本轮没有跟踪 GPU、内存、真实图片解码，也没有运行“同时去掉动画和 containment”的组合。建议先改动较小的动画项，再测二者交互，不能将两个单项百分比相加。

**字体与隐藏 HTML 是体积选择，计时收益证据较弱。** 基线观察窗口请求了 86,644 B（约 84.6 KiB）字体，系统字体方案为 0；结束布局相同，但拉丁品牌字形变化。隐藏 HTML 的 gzip 从 9,144 → 695 B，确定减少 8,449 B；它启动后本来就被移除，所以运行时 DOM 数不减少。两项的手机就绪时间没有稳定改善。

**别名表值得优化加载条件，不能删除。** 当前 9,461 条历史映射生成约 126.4 KB gzip 的启动依赖。空存储诊断减少约 147 ms / 120 ms（10.7% / 9.6%）；桌面基线范围 1,362–1,385 ms，清空表为 1,195–1,267 ms，手机分别为 1,182–1,292 和 1,119–1,150 ms。正式方案需确保旧分组、排除项、分类迁移及后续导入仍有映射可用，并继续保证迁移完成前不会覆盖存储；本轮没有实现或验证这样的条件加载。

**暂不改 Tooltip 与弹窗分块。** 两者未出现跨视口一致的大幅收益。Tooltip 改 title 还改变延迟、触屏和键盘提示体验；弹窗静态导入会增加初始入口负担，本轮未测首次打开这两个懒加载弹窗的成本。保持现状更合理。

## 前端设计结果

12 张浅色变体截图均无页面横向溢出；桌面/手机已加载图片分别为 144 / 72 张。另提供两张深色基线。截图位于本地 `.tmp/ablation/`，不混入正式网站资源。

| 设计项 | 实际观察 | 建议 |
|---|---|---|
| 紧凑 → 舒适密度 | 桌面首屏完整卡片 104 → 77；手机 28 → 15，增加名称且图片更大 | 保留切换；紧凑适合快速挑图，舒适适合核对名称，不强改默认 |
| 快捷按钮常显 | 手机每张图右上角出现 28×28 的排除按钮，覆盖部分耳朵、帽子等轮廓 | 保留悬停/键盘聚焦显现及详情操作，未经任务实验不改成全部常显 |
| 去掉卡片边框、底色、阴影 | 网格内容数和几何不变，画面更疏朗；各项点击边界在视觉上减弱 | 是审美与可发现性取舍，没有性能证据支持全面移除 |
| Web 字体 → 系统字体 | 中文主体和网格结构相近，Smoji 拉丁品牌及部分数字字形不同 | 可以作为流量优先选项，需接受跨系统字形差异 |
| 去掉模糊显现 | 解码结束后的布局与内容不变 | 优先候选；保留加载占位、错误提示和 reduced-motion 支持 |
| 深色基线 | 已检查手机底色、边界和主要操作层级 | 本轮未做完整对比度审计，不能据截图宣称 WCAG 合规 |

本轮以“阅读项目并做消融实验”为边界，没有改动产品实现或发布。推荐后续按独立小改动推进：先处理图片显现动画，再做 containment 组合复测；旧 HTML 清理与测试迁移另做；别名条件加载需要兼容性回归后再采用。
